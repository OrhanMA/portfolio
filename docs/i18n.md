# Internationalisation

Le site prend en charge les locales déclarées dans [`src/lib/i18n.ts`](../src/lib/i18n.ts). Le type `Locale` est la source de vérité pour le français et l'anglais.

Ce document définit où placer un texte et comment représenter une valeur localisée. Les étapes concrètes d'ajout sont décrites dans [`contributing.md`](./contributing.md).

## Sources de vérité

| Nature du texte | Emplacement |
| --- | --- |
| Navigation, boutons, messages d'état, métadonnées et descriptions d'accessibilité | `src/app/[locale]/dictionaries/fr.json` et `en.json` |
| Définitions, anecdotes et analyses de compétences | `src/lib/competences/` |
| Études de cas et leurs sections détaillées | `src/lib/realisations/` |
| Expériences, formations et données de parcours | Modules éditoriaux concernés sous `src/lib/` |
| Modules Odoo | `src/lib/odoo-projects.ts` |
| Corps des articles techniques | `fr.mdx` et `en.mdx` dans le dossier de l'article |

## Règles de représentation

- Une valeur disponible dans chaque langue utilise `Record<Locale, ...>` ou le type partagé `LocalizedContent`.
- Les dictionnaires `fr.json` et `en.json` gardent la même structure profonde. Les tests de parité comparent également les feuilles contenues dans les tableaux.
- Les noms de produits, technologies, marques, slugs, identifiants, extraits de code et valeurs d'API peuvent rester une chaîne unique lorsqu'ils sont intrinsèquement identiques.
- Une chaîne identique dans les deux langues n'est pas une traduction valide par défaut. Elle doit correspondre à une exception réelle de la catégorie précédente.
- Les liens internes commencent par `/${locale}` et conservent la destination logique lors d'un changement de langue.
- Les attributs `lang` des contenus doivent refléter la langue effectivement rendue.

## Articles bilingues

Chaque dossier d'article contient :

- `page.tsx`, qui valide la locale et fournit les deux composants MDX à `LocalizedArticle` ;
- `fr.mdx`, corps français ;
- `en.mdx`, corps anglais ;
- le layout ou les métadonnées partagées requis par la route.

Les deux corps conservent la même hiérarchie de titres `h2` et `h3` afin que le changement de langue puisse préserver une ancre équivalente. L'index de recherche et le temps de lecture utilisent le corps correspondant à la locale.

## Ajouter une locale

Ajouter une langue implique au minimum :

1. l'ajout de la locale dans `src/lib/i18n.ts` ;
2. un dictionnaire complet ;
3. toutes les valeurs `Record<Locale, ...>` des catalogues ;
4. la prise en charge dans le proxy, le layout, les métadonnées, le sitemap et le sélecteur de langue ;
5. les tests de parité, de navigation et de conservation du contexte.

Le sélecteur parcourt `locales` et ne doit pas coder une bascule spéciale limitée à `fr` et `en`.
