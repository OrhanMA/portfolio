# Internationalisation

Le site prend en charge les locales déclarées dans [`src/lib/i18n.ts`](../src/lib/i18n.ts). `Locale` est la source de vérité : un composant ou une fonction qui reçoit une langue supportée doit utiliser ce type, et une valeur disponible pour toutes les locales doit être déclarée avec `Record<Locale, ...>`.

## Où placer un texte

- Les textes d'interface, libellés, messages d'état, titres de navigation et descriptions d'accessibilité vont dans les deux dictionnaires JSON. Les deux fichiers doivent conserver exactement la même structure profonde ; le test de parité compare les chemins de toutes les feuilles, y compris dans les tableaux.
- Les données éditoriales riches restent dans leur module métier (`src/lib/competences`, `src/lib/realisations`, ou un module éditorial dédié). Leurs champs textuels localisés utilisent `LocalizedContent`, qui est un `Record<Locale, string>`.
- Les noms de technologies, produits, bibliothèques, marques, slugs, identifiants, extraits de code et valeurs transmises par une API peuvent rester une chaîne unique lorsqu'ils sont intrinsèquement identiques dans toutes les langues. Ils ne doivent pas être dupliqués artificiellement en `{ fr, en }`.
- Un article MDX peut rester dans sa langue éditoriale d'origine lorsqu'une traduction intégrale n'est pas publiée. Le dictionnaire doit alors traduire ses métadonnées et l'interface doit signaler cette limite à la personne qui lit l'article.

Une différence de formulation entre français et anglais est une traduction manquante, même si le texte est court. À l'inverse, une chaîne identique n'est volontairement non traduite que lorsqu'elle désigne un nom propre, une technologie, un identifiant ou un contenu éditorial dont la règle ci-dessus le permet. Toute nouvelle exception doit être documentée dans ce fichier et couverte par un test ou par le type de données qui la rend explicite.

Pour ajouter une langue, il faut l'ajouter à `locales` dans `src/lib/i18n.ts`, créer son dictionnaire, compléter les données éditoriales `Record<Locale, ...>`, puis vérifier `src/proxy.ts`, les métadonnées, le sitemap, le sélecteur et les tests de parité. Le sélecteur parcourt `locales` ; aucun composant ne doit coder une bascule spéciale entre seulement `fr` et `en`. Le détail des recettes et des commandes se trouve dans [`docs/contributing.md`](./contributing.md).
